# 企业统一 API / MCP / LLM 接入与权限治理平台设计

版本 1.6　｜　2026-11-19　｜　设计稿

## 1. 平台定位与建设范围

治理平台为企业员工、外部合作方及企业应用提供统一 API 入口。调用方使用平台签发的 API Key，经 Higress 访问获准使用的模型、MCP 工具或 HTTP 接口。管理员管理每个身份的可用权限；用户为客户端创建 Key 时，从中勾选该客户端需要的资源与操作。每次调用同时检查身份当前权限和 Key 的勾选范围。

天机是首个接入的外部业务平台。各业务平台维护自己的用户关系、角色与初始权限，通过各自的适配器转换为治理平台的标准记录。治理平台负责本地授权和决策，Higress 所在的调用链负责在转发前执行决定，上游业务服务负责对象级权限及业务状态检查。

首期范围包括身份同步、凭证生命周期、本地权限管理、模型开通审批、三类资源接入、LLM 与 MCP 用量明细、基础统计及软额度告警。完整账单结算、组织层级自动继承和复杂条件策略留待后续建设。

## 2. 账号、平台与角色身份

**平台与角色共同定义一个角色身份，账号通过角色指派取得该身份。** 平台指接入的业务系统，例如天机；同一个登录服务可以为多个业务系统提供认证。角色身份使用稳定标识组合 `(platform_id, role_id)`。显示名称用于界面展示。天机的“运营”和平台 B 的“运营”有各自的身份、授权记录和撤销范围。

| 对象 | 关键标识与关系 | 用途 |
|---|---|---|
| 账号 | `account_id`，类型为个人或企业应用 | 标识具体调用主体。企业应用独立开户、签发 Key、授权、审计和计量。应用责任人负责管理；应用背后的操作人无法从共享 Key 推断。 |
| 外部账号映射 | 平台、身份源、外部稳定用户 ID → 内部账号 | 同名、同邮箱均不触发自动合并。管理员可维护经核实的跨平台账号关联。 |
| 角色身份 | 平台 ID、角色 ID | 外部角色按所属平台登记。本地建立的角色也应指定适用平台。 |
| 角色指派 | 指派 ID、账号、角色身份、已同步状态、本地禁用标记及有效期 | 一名用户可持有多项指派；同一角色可由多人持有。指派记录标识某个账号以哪个身份调用。 |
| 组织及成员关系 | 平台、组织 ID、账号、关系状态 | 来源明确按组织授权时参与决策。父子组织及角色分类关系只供组织管理，首期不自动传递权限。 |

天机 Adapter 可以将“大角色／小角色”路径映射到该平台下的具体角色，用户取得对应指派。所属公司作为账号属性，不自动授予公司成员访问权。仅提供部门授权的来源可使用平台内账号和组织成员关系，无需虚构业务角色。

## 3. 资源目录与权限转换

资源目录为每个受保护目标分配稳定的内部 ID，记录所属服务、名称、状态、版本或配置变更时间，以及网关路由映射。外部平台角色可以被授权访问治理平台目录中的共享资源；共享资源仍按本次调用所用的平台身份分别判定。

| 资源 | 目录结构 | 首期授权动作 |
|---|---|---|
| MCP | Server → Tool，登记工具描述及 Schema | 进入 Server、发现指定 Tool、调用指定 Tool |
| LLM | Provider → Model，登记模型别名和可用上游 | 调用指定模型 |
| HTTP | Service → Route，登记 Method 与路由模板 | 访问服务或指定接口 |

MCP Server 入口许可与 Tool 执行许可分别管理。Provider 可用于筛选和批量选择模型。建议批量授权保存当次选中的子资源；日后新增工具或模型须另行开通。HTTP 服务级放行覆盖该服务内路由，需要限制个别接口时以更具体的本地拒绝规则控制。

### 3.1 从 Higress 添加资源

网关管理员在 Higress 维护路由、上游和插件。治理管理员进入资源目录，选择“从 Higress 添加”，通过只读连接刷新候选，补齐具体模型、工具或接口，再选择发布。首期采用主动拉取与手动刷新。外部业务平台的身份同步单独运行，资源刷新只能更新网关映射与候选记录。

以下为已核对的开源 Higress Console v2.2.6 后端 GET 接口。接入时核对实际版本、Console 基址、认证方式、可读范围和分页结果。治理后台只保存目录所需字段；原始配置可能包含凭据，不进入目录或操作日志。

| 对象 | Console 相对路径 | 导入粒度 |
|---|---|---|
| HTTP | `/v1/routes`、`/v1/routes/{name}` | 读取路由匹配条件。前缀路由下的具体 Method 和路径模板由管理员核实登记。[路由接口](https://github.com/higress-group/higress-console/blob/v2.2.6/backend/console/src/main/java/com/alibaba/higress/console/controller/RoutesController.java) |
| LLM | `/v1/ai/routes`、`/v1/ai/providers`，两者均支持按名称查询 | 读取明确配置的模型匹配条件、上游和回退配置。通配条件由管理员展开为允许发布的具体模型。[AI 路由](https://github.com/higress-group/higress-console/blob/v2.2.6/backend/console/src/main/java/com/alibaba/higress/console/controller/ai/AiRoutesController.java) · [供应商](https://github.com/higress-group/higress-console/blob/v2.2.6/backend/console/src/main/java/com/alibaba/higress/console/controller/ai/LlmProvidersController.java) |
| MCP | `/v1/mcpServer`、`/v1/mcpServer/{name}` | 读取 Server 配置并提取可识别的静态工具。代理已有服务时，通过授权的 `tools/list` 或人工登记补齐工具及 Schema，记录清单来源。[MCP 接口](https://github.com/higress-group/higress-console/blob/v2.2.6/backend/console/src/main/java/com/alibaba/higress/console/controller/mcp/McpServerController.java) |
| 插件 | `/v1/routes/{routeName}/plugin-instances` 及相应全局、域名、服务级查询 | 核对目标路由实际适用的鉴权配置，再通过受控调用验证执行效果。[插件实例](https://github.com/higress-group/higress-console/blob/v2.2.6/backend/console/src/main/java/com/alibaba/higress/console/controller/WasmPluginInstancesController.java) |

### 3.2 发布与下线

| 状态 | 管理动作 | 用户与已有 Key |
|---|---|---|
| 候选 | 按网关实例、来源对象和具体目标去重。管理员核对稳定资源 ID、实际目标、鉴权覆盖和业务责任方。 | 仅管理员可见。 |
| 已发布 | 在隔离的验收路由上用相同配置验证允许与拒绝结果，核对生产映射后记录发布人、配置版本和时间。 | 模型可按目录可见范围发起申请；获准的资源及动作可选入 Key。 |
| 暂停 | 确认目标消失、映射变化或鉴权配置失效时暂停，刷新授权缓存。修复后重新核验、显式发布。 | 停止新勾选与调用，保留已有绑定及历史记录。 |
| 下线 | 管理员结束资源对外服务，记录原因并使发布版本失效。 | 已有 Key 对该资源的后续请求拒绝；其他资源照常使用。 |

刷新按完整分页读取结果对账。超时、鉴权失败或部分分页缺失时保留上次完整快照，显示异常和最后成功时间；不能据此批量下线。实际请求仍须匹配已核验的目标。网关管理员变更受保护路由或移除鉴权前，应先暂停对外入口，验证新配置后再开放。若改接的是另一项业务能力，创建新的资源 ID 并重新授权，防止旧 Key 沿用原勾选项访问新能力。

### 3.3 外部身份与权限适配器输出契约

各适配器输出账号映射、角色定义与指派、组织成员关系、资源映射和外部授权基线。管理后台和授权引擎使用以下统一策略字段。

| 字段 | 含义 |
|---|---|
| 平台范围 | 本条授权适用的业务平台 ID；所有主体类型均限定适用平台。 |
| 主体 | 账号、角色身份或组织及其内部标识。账号级授权如只面向特定角色，应同时指定该角色条件。 |
| 目标及动作 | 内部资源类型、资源 ID 和动作；权限组通过关联表展开为相同结构。 |
| 效果及条件 | 允许或拒绝、状态、有效期；可限定经核验的角色和组织。 |
| 归属与追溯 | 外部基线记录来源 ID、外部记录标识、同步与映射版本；本地规则记录操作人、时间、原因及变更版本。 |

例如，天机授予产品经理调用某个工具的权限时，输出“天机／角色 R17／工具 T3／调用／允许”；平台 B 授予研究部使用模型 M2 时，输出“平台 B／组织 D8／模型 M2／调用／允许”。前者匹配天机角色指派，后者匹配平台 B 内有效部门成员，两条记录可由同一引擎执行。

### 3.4 外部身份同步与失效

支持首次全量导入、增量或定时同步；来源支持事件时可接入变更通知。以来源记录标识和版本处理重复、乱序和重试。只有确认完整的快照才能据缺失记录推断删除。同步保留上次结果、变更范围和异常原因。

映射失败或无法表达外部限制条件时，隔离受影响的授权范围，禁止把附条件的允许导入为无条件允许。请求以治理平台已提交的记录判定。外部角色变动在成功同步前沿用上次状态；同步确认撤销后，对应指派失效。管理员可在身份管理页单独禁用某个账号的某项指派；后续同步仍显示持有该角色时，保留本地禁用。解除本地禁用后重新按当前基线及有效期判定。禁用指派须刷新关联凭证的授权缓存。资源授权的本地覆盖只影响可用资源，不能恢复失效的指派。

## 4. 本地权限管理与模型审批

管理员可在权限页按平台、主体和资源查询，查看外部基线、本地设置、最终结果和命中原因。页面提供“允许”“拒绝”“恢复外部基线”三种操作。保存时记录修改前后值、原因和操作人，更新策略版本并刷新受影响的缓存。批量操作应展示影响的平台、主体和资源清单。

平台按以下顺序计算身份当前可用的权限，供创建 Key 和请求校验共用。

1. 校验账号、平台接入资格、所用角色指派或组织关系及资源状态。必要身份条件失效时拒绝。
2. 匹配适用的本地账号、角色及组织规则。本地拒绝优先；其余情况下，有本地允许即计入身份可用权限。管理员可以覆盖外部资源基线中的明确拒绝。
3. 没有命中本地设置时，计算当前外部基线。适用的拒绝优先，其次为允许；缺少有效允许时拒绝。

模型申请由申请人选择平台身份及模型，管理员审核。审批通过后创建限定申请账号、所选平台身份和模型且带有申请记录引用的本地授权，模型进入该身份的可选范围。用户在新 Key 或已有 Key 中勾选该模型后才能通过这把 Key 调用。管理员也可为角色或组织批量开通。审批记录保留申请人、申请理由、平台身份、模型、审批人、结论和时间。MCP 权限按同步基线和本地设置管理。

## 5. Key 签发与请求身份

1. **确定身份。** 仅有一个有效身份时自动选中；有多个时选择“平台／角色”。企业应用由其管理员操作。无角色来源按账号和平台确定身份。
2. **勾选用途。** 页面只展示已发布且该身份当前获准的资源和操作。模型按模型选，MCP 按工具及操作选，HTTP 按接口选。批量选择按当时选中的具体项目保存。MCP 工具所需的 Server 入口和发现操作可随选择一并展示、校验和保存；入口许可不会选中同 Server 的其他工具。
3. **签发或修改。** 服务端重新校验所选项目与身份权限，保存 Key 及其范围。已有 Key 可在同一身份下增减勾选项。保存变更时记录操作人、时间和范围版本，并刷新决策缓存。

凭证记录保存 Key ID、账号、平台、角色指派引用（如适用）、密钥摘要、前缀、有效期和状态。勾选明细以“Key ID、资源 ID、动作”关联。密钥使用高熵随机值，创建时展示一次，支持轮换、过期、吊销和审计。轮换沿用原勾选范围。

例如，同一运营身份分别创建报表 Key 和业务 Key，前者只选“查询订单”，后者另选“取消订单”。管理员撤销该身份的查询权后，两把 Key 都无法再查询；后来新增的导出权，只会出现在可选列表。禁用身份后，该身份下的全部 Key 均无法调用。

网页切换角色不会改变已签发 Key 的绑定。首次接入按本地指派判定；若某来源需要同步网页活动角色，应单独约定同步范围和更新时限，接收该状态后才纳入本地判定。

## 6. Higress 请求执行

客户端向统一地址发送 API Key。Higress 调用 External Auth 和网关授权适配器验证凭证；适配器解析账号、平台和角色指派，生成可信上下文。网关清理客户端传入的同名身份头，只接受认证链生成的白名单字段。每次对实际目标校验发布状态、当前路由映射、Key 有效性、身份当前权限和该 Key 勾选的资源及动作，全部满足才放行。MCP 列表过滤使用同一交集。每笔决策记录请求 ID、Key ID、决策 ID、资源、动作、策略版本及 Key 范围版本。

| 调用路径 | 转发前的检查 | 执行与验收重点 |
|---|---|---|
| 模型 API | 根据协议解析实际请求模型，将别名解析到稳定模型 ID 后校验调用权。 | AI Proxy 按获准目标转发。回退到另一模型时重新授权；同一路由请求未开通模型应拒绝。供应商密钥仅由服务端保管。 |
| 网关提供 MCP 工具 | 校验 Server 入口；按可见权限过滤工具列表，对每次工具调用解析 Server 和 Tool 并校验调用权。 | 即使客户端记住工具名，撤权后直接调用也应被拒绝。 |
| 网关代理已有 MCP 服务 | 在可解析 MCP 消息的位置执行同样的列表过滤和调用校验。 | 验证部署版本和转发模式；插件无法覆盖时，路由到执行这两项检查的 MCP 授权代理，通过验证后再开放。 |
| HTTP API | 根据实际匹配路由和 Method 取得服务及接口 ID，执行访问授权。 | 上游或指定业务执行服务校验业务对象范围、操作状态。开放接口前登记具体责任方。 |

方法和路由能唯一标识目标时，授权服务直接按该映射判定。多个模型共用地址时，须在转发前从可信解析结果取得模型；使用 External Auth 转发请求体时应针对该路由配置并验证大小限制。若无法在回退处复核目标权限，则关闭跨模型回退。[External Auth 配置](https://higress.cn/docs/latest/plugins/authentication/ext-auth/)

MCP 优先由鉴权服务生成有效工具范围，网关覆盖客户端同名头，MCP Server 插件按可信白名单执行。插件将缺失或空字符串的动态白名单解释为沿用静态配置，不能用空字符串表达零权限。首期零可用工具时直接拒绝该 Server 的业务访问；若需保留列表会话，应先验证空清单和直接调用拒绝。分别验证托管工具与代理模式。若发现和调用权限不同，执行点须逐动作校验；单一白名单不能表达差异时使用协议授权代理。[MCP Server 插件说明](https://higress.cn/docs/ai/mcp-server/)

受保护资源在认证或授权不可用、目标无法识别时拒绝。下游只接受受信网关或授权代理的调用。对重复使用相同授权的路由可以共用入口认证配置，仍按实际请求资源做最终决策。

Higress Consumer 供依赖该技术身份的原生插件使用。按组织或应用配置 Consumer 的可行性须在目标环境验证；平台账号、角色授权与 Key 生命周期独立维护。对注入身份头、动态工具清单和插件执行顺序分别验收。

## 7. 用量、审计与额度

调用事件保存请求发生时的账号、账号类型、平台、角色、组织（如适用）、Key ID、时间、目标资源、结果与耗时。请求 ID 关联完整链路，尝试 ID 区分上游重试，事件 ID 用于投递去重。按调用时快照聚合，保留权限变更前的历史归属。

| 类型 | 原子事件与统计口径 |
|---|---|
| LLM | 记录请求模型、实际模型、Provider、输入和输出 Token，以及上游提供的缓存、推理用量。逻辑调用按请求统计，上游消耗按尝试统计。流式中断或缺少 Usage 时标记不完整，保留已知字段。 |
| MCP | 业务调用统计限定于 `tools/call`，记录 Server、Tool、授权结果和执行结果，分别记录授权（允许、拒绝）和执行（未执行、成功、失败、结果未知）。鉴权拒绝只计拒绝；确认发起执行后即计一次执行尝试，包括工具业务失败。仅确认转发、缺少执行回执时保留转发事实及未知结果。`initialize`、列表和通知进入协议运维日志。 |
| HTTP | 首期保留访问日志、授权审计和运维指标，独立业务计费按需扩展。 |

LLM 采集优先验证 Higress AI Statistics、可信自定义属性和访问日志中 `wasm.ai_log` 的输出。用量统计按账号、平台角色、Key、组织、工具和模型聚合；高基数身份字段保留在日志或事件库。日志默认不采集 Prompt、Completion 及任何密钥明文。

授权服务记录决定和原因，网关记录路由匹配、是否转发和尝试 ID，模型或工具执行组件提供实际结果。无效 Key 的账号归属记为未知。运营按请求 ID 查询“未发布、身份失效、Key 未勾选、上游失败或用量不完整”等原因。首期在现有日志看板提供查询和聚合；按账号、平台、Key ID 的可见范围授权。只有现有看板无法满足运营使用时才增设专门的用量页面。[AI Statistics 文档](https://higress.cn/docs/latest/plugins/ai/api-o11y/ai-statistics/)

首期按用户或组织设置软额度和告警，达到阈值后仍可调用。QPS 和突发流量由网关保护。模型费用后续按供应商、模型及价格版本核算，MCP 独立计算。管理审计覆盖开户、同步、权限覆盖、审批、凭证变更及管理员操作。

## 8. 管理后台与部署

后台提供身份与同步、资源目录、权限管理、模型审批、凭证、用量与审计、网关只读连接配置七类入口。个人可管理自己的 Key 并申请模型；应用管理员在授权范围内管理应用凭证；权限管理员按平台范围配置和查询策略。

管理后台及身份、资源、审批、凭证、授权模块优先采用模块化单体，复用现有前端技术栈和 MySQL 或 PostgreSQL。网关授权适配器独立部署并可横向扩展。Redis 可用于带版本的短期认证与决策缓存；最终决策缓存须区分 Key ID、Key 范围版本、身份与策略版本、资源发布版本和动作。上线前约定并实测吊销和撤权的最大生效时延。

计量消费可独立部署，优先复用现有日志服务；需独立事件管道时再评估 Kafka 与 ClickHouse。监控同步滞后、认证与授权耗时、拒绝原因、上游错误、事件丢失或积压。具体组件组合以现网版本、容量和验证结果为准。

## 9. 实施顺序与验收

| 阶段 | 交付范围 | 验收场景 |
|---|---|---|
| 一、验证调用链 | 在实际 Higress 版本上验证 External Auth、模型目标识别、两类 MCP 路径、AI Statistics 及必要的 Consumer 集成。 | 拒绝伪造的身份头；同路由两个模型独立授权；两个并发用户的工具可见性与执行权分别生效；验证各协议流式用量及断连行为。 |
| 二、接入身份与凭证 | 接入天机认证、同步、角色映射、企业应用账号和 Key 管理。 | 以天机及第二个模拟平台的同名角色验证指派隔离；吊销一把 Key 或撤销一项角色指派，另一平台的合法调用仍成功。 |
| 三、交付授权与业务接入 | 交付目录、权限页面、审批、三类网关执行路径及业务服务责任清单。 | 外部拒绝经本地允许后可勾选，选入 Key 后可调用；再次同步仍可用，恢复拒绝基线后调用被拒。新增获批模型在旧 Key 上须显式选入。同身份两把 Key 的勾选范围独立，取消勾选后命中旧缓存也不得越权。检查模型别名、跨模型回退、工具直接调用及对象级权限。 |
| 四、交付计量与运营 | 交付原子事件、聚合、软额度告警、审计和运行监控。 | 重复投递不重复入账；上游重试可核对；缺失 Usage 能区分；网页切换按接入契约验证；认证故障及撤权传播符合上线要求。 |

**贯穿验收。** 从实际 Console 导入一个 MCP Server 和两个工具。刷新两次无重复、候选阶段不可选；发布后，让同一身份的 Key 只勾选其中一个工具。经 Higress 调用，确认获准工具可执行，未勾选工具在列表中不可见且直接调用被拒。按请求 ID 对照授权记录、转发和执行回执，验证拒绝请求未计入执行次数。最后下线已勾选工具，核验缓存传播时限内旧 Key 停止访问、其他已发布资源仍可用。另用一次模型流式请求核对实际目标、Usage 和 Key 归属。记录 Console 与插件版本、对应路由、实测结果及异常项。

首期上线依据上述场景在实际环境中的结果。后续新增来源时交付独立 Adapter、映射样例和验收数据，验证其角色范围、组织授权及状态失效语义。
